# Перенесення архіву OCS і старі адреси

Посібник для закладів, які переходять з Open Conference Systems (OCS 2.x) на OJS 3.5 з плагіном Conference Manager. Він описує, як перенести опубліковані доповіді й зробити так, щоб старі посилання на них вели на нові сторінки.

## Що переноситься

- **Переноситься:** опубліковані доповіді з метаданими й PDF.
- **Не переноситься:** реєстрації, розклади, рецензії й неопубліковані подання. Їх варто залишити в статичній копії старого сайту в режимі лише для читання.
- **DOI.** Якщо частина матеріалів уже є в репозиторії закладу (DSpace тощо), заздалегідь вирішіть, де реєструється DOI. Одна праця має мати DOI лише в одній системі.

## Порядок роботи

Працюйте з **копією** бази й файлів OCS, а не з робочим сервером.

1. **Перенесіть доповіді скриптом.** Див. розділ «Скрипт перенесення» нижче. Він сам розгортає копію OCS, експортує доповіді, імпортує їх в OJS 3.4, оновлює до OJS 3.5 і звіряє результат за кожним виданням.
2. **Перегляньте результат.** Відкрийте тестову OJS 3.5 зі скрипта й перевірте кілька доповідей кожного видання: назви, авторів, анотації, PDF.
3. **Перенесіть у робочий журнал.** Експортуйте випуски з тестової OJS 3.5 у Native XML і імпортуйте в робочий журнал по одному випуску в години низького навантаження. Спершу зробіть це на тестовій копії робочого сайту з плагіном.
4. **Зіставте старі адреси.** Див. розділ «Старі адреси» нижче. Готові списки доповідей скрипт кладе в теку `legacy/`.
5. **Налаштуйте переадресацію на сервері старого домену.** Див. «Карта переадресацій».
6. **Вимкніть OCS.** Після цього місяць стежте за помилками 404 у журналі сервера.

## Скрипт перенесення

Скрипт `tools/ocs-migration/migrate.sh` є в репозиторії плагіна (у пакет для OJS він не входить). Запускайте його на окремій машині з Docker, не на робочому сервері.

```
tools/ocs-migration/migrate.sh ocs-dump.sql.gz /шлях/до/files-ocs
```

- Перший параметр: дамп бази OCS (`.sql` або `.sql.gz`).
- Другий параметр: тека файлів OCS (`files_dir` з `config.inc.php` OCS). Без неї доповіді перенесуться без PDF: на місці файлів будуть порожні заглушки, і звірка це покаже.
- Інтернет потрібен лише на першому кроці, щоб завантажити OCS 2.3.6 та інструмент [ocs-to-ojs](https://github.com/jonasraoni/ocs-to-ojs) на перевірених версіях. Усі контейнери з даними працюють у внутрішній мережі Docker без доступу до інтернету, тож персональні дані з дампу не виходять за межі машини.

Що робить скрипт:
1. Відновлює дамп у MariaDB.
2. Експортує опубліковані доповіді через ocs-to-ojs на PHP 5.6. Конференція стає журналом, видання OCS стає випуском, секція стає розділом.
3. Виправляє рік випуску: бере його з дати **початку** видання. Сам ocs-to-ojs бере рік з дати закінчення, а її в OCS часто ставлять на роки вперед, щоб сайт видання не закривався. Щоб брати рік з дати закінчення, задайте `YEAR_FROM=end`.
4. Імпортує доповіді в OJS 3.4. Скрипт виправляє в ocs-to-ojs відому помилку: в офіційних образах OJS кирилиця з бази OJS ставала порожнім рядком, і жодна доповідь не імпортувалася.
5. Оновлює OJS до 3.5.
6. Звіряє з OCS кожне видання: кількість доповідей, кількість файлів і скільки файлів мають вміст. Таблиця зберігається у `verify.txt`. Якщо щось не збігається, скрипт завершується з помилкою.
7. Готує для кожної конференції список доповідей для старих адрес (`legacy/{конференція}.tsv`).

Результат: контейнер `ocsmig-ojs35` з тестовою OJS 3.5 (вхід admin / admin12345) і база `ojs` у контейнері `ocsmig-db`. Тека роботи за замовчуванням `./ocs-migration-work`, її можна змінити змінною `WORK`. Після перенесення видаліть контейнери й теку роботи, бо в них персональні дані.

## Старі адреси

Типова адреса доповіді в OCS 2.x має вигляд `/{конференція}/{видання}/paper/view/{номер}`, наприклад `/SRE/SRE-2025/paper/view/123`. Плагін має знати, яка стаття OJS відповідає кожному номеру доповіді OCS.

### 1. Перелік доповідей з бази OCS

Виконайте на **копії** бази OCS такий запит:

```sql
SELECT p.paper_id AS ocs_paper_id,
       c.path     AS conference,
       sc.path    AS sched_conf,
       (SELECT ps.setting_value FROM paper_settings ps
         WHERE ps.paper_id = p.paper_id AND ps.setting_name = 'title'
         ORDER BY ps.locale = 'uk_UA' DESC, ps.locale LIMIT 1) AS title
  FROM published_papers pp
  JOIN papers p       ON p.paper_id = pp.paper_id
  JOIN sched_confs sc ON sc.sched_conf_id = p.sched_conf_id
  JOIN conferences c  ON c.conference_id = sc.conference_id
 WHERE p.status = 3  -- лише опубліковані: у published_papers лишаються й відхилені пізніше
 ORDER BY p.paper_id;
```

Збережіть результат у файл, розділений табуляцією, наприклад так:
`mysql --batch -u ocs -p ocs_copy -e "…запит…" > papers.tsv`.

Плагін приймає CSV з комою, крапкою з комою або табуляцією. Перший рядок має містити назви колонок:
- обов'язкові колонки: `ocs_paper_id`, `conference`, `sched_conf`;
- для зіставлення за назвою: `title`;
- для точного зіставлення: `submission_id`, номер статті в OJS.

Схему бази заклади інколи змінювали. Перевірте запит на копії і, якщо треба, поправте назви таблиць.

### 2. Зіставлення

1. У розділі **Конференції** натисніть **Старі адреси OCS**.
2. Виберіть файл у полі **Файл CSV** або вставте його вміст.
3. Натисніть **Завантажити й зіставити**.

Як плагін зіставляє доповіді:
- якщо є `submission_id`, береться саме ця стаття (вона має бути опублікована в цьому журналі);
- якщо `submission_id` немає, береться опублікована стаття з тією самою назвою будь-якою мовою (регістр і розділові знаки не важать);
- якщо статей з такою назвою кілька, вибирається та, що опублікована в рік зі шляху видання (`SRE-2025` дає 2025) або наступного року.

Звіт показує:
- пропущені рядки з причиною;
- доповіді, для яких знайшлося кілька статей;
- доповіді без статті.

Для доповідей зі звіту додайте `submission_id` і завантажте файл ще раз: наявні рядки оновляться.

Поле **Перевірити адресу** показує, куди веде будь-яка стара адреса.

### 3. Шаблони адрес

Типові шаблони охоплюють `paper/view`, `paper/viewPaper`, `paper/download` і `paper/viewFile`, з префіксом `index.php/` і без нього. Якщо OCS у закладі мав інші адреси, змініть шаблони в розділі **Шаблони старих адрес**.

Частини шаблону:

| Частина | Що означає |
|---|---|
| `{conference}` | шлях конференції |
| `{schedConf}` | шлях видання |
| `{id}` | номер доповіді (обов'язково) |
| `{fileId}` | номер файлу |
| `{any}` | будь-яка одна частина адреси |

Шаблон має містити хоча б одну незмінну частину, наприклад `paper`.

### 4. Карта переадресацій

Кнопки в розділі **Карта переадресацій для веб-сервера** дають готові файли для адміністратора сервера старого домену:
- **nginx.** Блок `map` вставте в `http { }`, блоки `location` вставте в `server { }` старого домену. Потім виконайте `nginx -t` і перезавантажте nginx.
- **Apache.** Файл «карта» покладіть туди, куди вказує рядок `RewriteMap` у файлі «правила» (за потреби змініть шлях). Правила вставте в `<VirtualHost>` старого домену: у `.htaccess` `RewriteMap` не працює. Потрібен `mod_rewrite`. Потім виконайте `apachectl -t` і перезавантажте Apache.

Адреси, яких немає в карті, сервер обслуговує як раніше, наприклад зі статичної копії OCS. Після кожного нового імпорту доповідей завантажте карту знову.

### 5. Без карти

Якщо старий домен веде на цей сайт OJS і шлях журналу збігається з першою частиною старих адрес (журнал `SRE` для адрес `/SRE/SRE-2025/…`), плагін сам відповідає переадресацією 301 на статтю. Карта в такому разі не обов'язкова, але з картою сервер відповідає швидше.

## Перевірка

- Візьміть 200 випадкових старих адрес (наприклад, з журналу доступу старого сервера) і перевірте, що кожна веде на сторінку статті з відповіддю 200.
- Після вимкнення OCS місяць стежте за помилками 404 на старому домені.
