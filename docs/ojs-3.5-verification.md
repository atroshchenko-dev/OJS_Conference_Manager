# Звірка з OJS 3.5.0-6: що в ескізах плану треба змінити

Перевірено 14.11.2026 на коді образу `pkpofficial/ojs:3_5_0-6` і гілці `pkp-lib stable-3_5_0`, а також встановленням плагіна в справжній OJS 3.5.0-6 (MariaDB 11.4 і PostgreSQL 16). Кожен пункт нижче вже враховано в коді (п. 1–11 — версія 0.1, п. 12–15 — 0.2, п. 16–20 — 0.3).

| # | Ескіз у плані v2 | Як насправді в OJS 3.5 | Що зроблено |
|---|---|---|---|
| 1 | `setEnabled($enabled, $contextId)` у головному класі (25.2) | `LazyLoadPlugin::setEnabled($enabled)` має **один** параметр і бере контекст із запиту | Профіль створюється як чернетка при першому відкритті. Групи користувачів (REG-01) створюються в перевизначеному `setEnabled($enabled)` для поточного контексту і ліниво при першому зверненні до API (0.2) |
| 2 | Колбек хука `APIHandler::endpoints::plugin` як `(string $hookName, array $args)` (25.6) | `Hook::run()` передає аргументи **розгорнутими**: `fn (string $hookName, APIRouter $router)`. `Hook::call()` (застарілий) передає масив | Сигнатуру виправлено; власний хук `ConferenceManager::jurisdictions` викликається через `Hook::run` |
| 3 | Кілька API-контролерів зі шляхом `conference` (25.6) | Один контролер на шлях; повторна реєстрація кидає виняток; шлях зіставляється за префіксом | Один контролер на `conference`; нові модулі додають маршрути до нього (docs/architecture.md) |
| 4 | Міграція з конструктором без параметрів (25.3) | Для `<migration class>` з `upgrade.xml` OJS викликає `new $class($installer, $attributes)` | Конструктор приймає обидва параметри |
| 5 | Власна властивість `$connection` у міграції | `Illuminate\Database\Migrations\Migration` вже має `protected $connection`; `private` з такою назвою — фатальна помилка | Властивість названо `$explicitConnection` (знайдено лише встановленням у справжній OJS) |
| 6 | Нові колонки в тому самому класі міграції під `hasColumn` (25.3) | Під час оновлення в пам'яті вже **старий** клас міграції, тож новий код у ньому не виконається в цьому запиті | Кроки міграції — окремі файли, знаходяться з диска (перевірено синтетичним оновленням) |
| 7 | `isEnabledFor()` порівнює з контекстом сайту `0` | `Application::SITE_CONTEXT_ID === null` у 3.5 | Перевірка лише на `null` |
| 8 | — | Виняток у колбеку хука плагіна OJS логує й ковтає; запит до API тоді повертає 404 «endpoint not found» | Для діагностики дивитися журнал PHP; інтеграційний тест ловить такі випадки |
| 9 | Модифікатори Smarty з функціями PHP (`in_array`) | Smarty 4.5: виклик функцій PHP як модифікаторів застарів | Дані для шаблонів готуються в PHP |
| 10 | — | URL компонентів (`$$$call$$$`) — без сегмента мови; URL сторінок — з ним (`/confa/en/...`) | Враховано в тестах |
| 11 | Встановлення без shell (контрольна точка 29.01.2027) | `PluginHelper::installPlugin` / `upgradePlugin` — ті самі методи, що викликає форма завантаження плагіна | `ci/integration/run.sh` викликає їх напряму, як це робить форма; повна перевірка через веб-інтерфейс (Cypress) — завдання наступних спринтів |
| 12 | `Schema::get::publication` | Викликається через застарілий `Hook::call()`: колбек отримує `(string $hookName, array $args)`, схема — `$args[0]` за посиланням | Так і зроблено (на відміну від хуків з `Hook::run`, п. 2) |
| 13 | Групи користувачів через DAO | `UserGroup` у 3.5 — модель Eloquent: `new UserGroup([...roleId, contextId, permitSelfRegistration...])->save()`, назви — налаштування `name`, `abbrev`, `nameLocaleKey` | `Core\UserGroupGateway`; id груп зберігаються в налаштуваннях плагіна, тому повторний виклик нічого не дублює |
| 14 | Часовий пояс контексту | У контексту OJS 3.5 немає власного часового поясу, лише серверний (`config.inc.php`) | Пояс видання за замовчуванням — з профілю юрисдикції (UA: `Europe/Kyiv`), інакше серверний |
| 15 | `Issue::setTitle($title)` | `setTitle($title, $locale)` типізовано на рядок; локалізований масив — через `setData('title', [...])` | Так і зроблено в `Core\IssueGateway` |
| 16 | Сторінки плагіна | Хук `LoadHandler` викликається через `Hook::call()` з масивом посилань `[&$page, &$op, &$sourceFile, &$handler]`; оператор сторінки з довільним шляхом (`conference/{адреса}`) підміняється на `view` | `ConferenceManagerPlugin::loadPageHandler` |
| 17 | Інтерфейс менеджера | Сторінки бекенду — один Vue-застосунок; плагін реєструє компонент через `pkp.registry.registerComponent()`, скрипт має йти **після** `js/build.js` (пріоритет `STYLE_SEQUENCE_LAST`), меню — через `TemplateManager::setupBackendPage` і стан `menu` | `js/editionsManager.js`, `ManageConferenceHandler` |
| 18 | Планувальник | Плагін реалізує `HasTaskScheduler::registerSchedules(PKPScheduler)`; завдання видно в `scheduler.php list` | `EditionWindowsTask`, кожні 15 хв |
| 19 | Сторінки рівня сайту | На `/index/...` завантажуються лише плагіни, увімкнені на рівні сайту; публічний API — `isSiteWide()` і `PublicAccessPolicy` | «Майбутні заходи» вмикаються саме так |
| 20 | — | OJS 3.5.0-5 на перший запит сторінки в сесії відповідає переадресацією на ту саму адресу | Тести йдуть за переадресаціями й зберігають cookie |

Ще не перевірено (залишається у спайках спринту 1 за планом): кроки майстра подання, кнопки рішень 9xx у Vue-воркфлоу, QR у mPDF, вимкнення прийому подань, злиття користувачів.
